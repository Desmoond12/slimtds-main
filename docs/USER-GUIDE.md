# AffMoment TDS — инструкция оператора

> Актуально на 2026-08-18. Этот файл — источник; docx-версия генерируется из него
> (`docs/AffMoment-TDS-инструкция.docx`). При изменении механики трекера обновлять оба.

## Что это

Самописный трекер (TDS): принимает клики с ваших SEO-сайтов, маршрутизирует посетителей
по кампаниям/потокам на офферы партнёрок, ловит постбеки (регистрации, депозиты, revshare)
и сверяет ваши цифры с отчётами партнёрок.

- Адрес админки (локально): `http://localhost:8080/admin/login`
- Логин/пароль: из файла `.env` (`ADMIN_LOGIN` / `ADMIN_PASSWORD`)
- Всё крутится в Docker; если сайт не открывается — запустить Docker Desktop и подождать ~30 секунд.

## Порядок настройки (важно соблюдать)

Сущности зависят друг от друга, поэтому создавать их надо в таком порядке:

**1. Партнёрская сеть** (меню «Партнёрские сети») — *нужна, только если партнёрка диктует
свои имена параметров постбека или хочется защиты/маппинга. Можно пропустить и вернуться позже.*

- «Имена параметров постбэка» — заполнять, только если ПП шлёт поля под своими именами
  (например `clickid` вместо `subid`, `amount` вместо `payout`). Если постбек-URL пишете
  вы сами — оставить дефолты.
- «Перевод значений статуса» — если ПП шлёт статусы кодами (`1=approved`, `0=rejected`).
- «Перевод значений событий» — приводит названия событий ПП к вашему словарю:
  `firstDeposit=ftd`, `registration=reg`. Незамапленные значения проходят как есть,
  постбек никогда не теряется из-за этой таблицы.
- «IP-адреса источника постбеков» — опубликованные постбек-IP партнёрки (по строке,
  можно CIDR). Заполнено → постбеки с чужих IP отклоняются (защита от фейковых депозитов
  по утёкшему токену). Пусто → без ограничений.

**2. Оффер** (меню «Оферы») — конечная ссылка партнёрки.

- URL — ссылка ПП; обязательно вставить `{click_id}` в их subid-параметр, например
  `https://pp.com/click?offer=123&sub_id={click_id}`. Доступны и другие макросы:
  `{country}`, `{device_type}`, `{payout}` и т.д.
- Привязать «Партнёрскую сеть», если создали (шаг 1).
- После сохранения у оффера появляется **postback token** — он понадобится для URL постбека.
- Офферы глобальные: один оффер можно использовать в нескольких кампаниях.

**3. Кампания** (меню «Кампании») — точка входа трафика.

- Slug — то, что стоит в ссылке клика: `https://ваш-трекер/slug`.
- Trash mode — что видит посетитель, если ни один поток не подошёл (404/403/редирект).
- Можно привязать сеть и на уровне кампании (для campaign-токена).

**4. Поток (flow)** внутри кампании — правило «кому какой оффер».

- Фильтры: гео, устройство, ОС, бот/не бот, реферер и т.д. Внутри группы условия по И,
  между группами — ИЛИ.
- Target: список офферов с весами — это и есть сплит-тест (50/50, 70/30...).
- Потоки проверяются сверху вниз, первый подошедший выигрывает.
- Клоакинг: поток с фильтром `is_bot = 1` → редирект на белый сайт (см. `docs/CLOAKING.md`).

**5. Постбек-URL для партнёрки** — отдать ПП ссылку вида:

```
https://ваш-трекер/postback?token=<postback_token_оффера>&subid={их_макрос_клика}&status={их_статус}&payout={их_сумма}&event_type={их_событие}&external_id={их_id_транзакции}
```

- `token` — из оффера (или campaign-токен из кампании, тогда оффер определится по клику).
- `event_type` необязателен (без него событие пишется как `conversion`); с ним
  REG/FTD/редепозиты живут отдельными записями на одном клике.
- `external_id` — id транзакции/игрока у ПП; защищает от задвоения.

**6. Проверка** — меню «Лог постбеков»: там тестер (реально бьёт по `/postback`)
и лог каждого удара с результатом (OK_NEW / OK_DUPLICATE / CLICK_NOT_FOUND / FORBIDDEN_IP...).

## Ежедневная работа

- **Клики** — каждый клик: гео, устройство, бот, куда ушёл.
- **Конверсии** — все события с фильтрами по статусу/типу события; KPI-карточки
  approved/pending/hold/rejected.
- **Статистика** — по кампаниям, офферам, гео, сайтам (какой сайт реально зарабатывает).
- **Сверка** (Партнёрские сети → Сверка) — ваши цифры против цифр ПП:
  1. Скачать у партнёрки отчёт CSV (по дням).
  2. Партнёрские сети → «Отчёты ПП» → загрузить файл → замапить колонки (запоминается).
  3. Открыть «Сверка»: таблица по дням и событиям, наши/ПП, дельта; расхождения больше
     порога подсвечены. Смещение ±1 день вокруг полуночи — норма (разные таймзоны).

## Что важно знать

- **Клик не найден (CLICK_NOT_FOUND) в логе постбеков** — партнёрка потеряла/обрезала
  subid, или клик старше retention (365 дней). Если таких много — алерт придёт сам
  (при настроенном Telegram).
- **Telegram-уведомления** — опциональны (`TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` в `.env`).
  Не настроены → просто ничего не шлётся, на работу трекера не влияет. Уведомления
  уходят через очередь, посетителей и постбеки не тормозят.
- **Отрицательный payout — это нормально** при RevShare (игрок выиграл больше, чем
  проиграл). Трекер его принимает и учитывает.
- **Дубли депозитов**: один и тот же `external_id` (транзакция) по одному типу события
  учитывается один раз, даже если ПП прислала его на два разных клика.
- **Бэкапы** — каждую ночь автоматически (`var/backups/`); восстановление проверено.
- **Правки офферов/потоков** применяются за ~5 секунд (кэш потоков).

## Если что-то сломалось

1. `docker compose ps` в папке трекера — все контейнеры должны быть Up.
2. «Лог постбеков» в админке — первый источник правды по конверсиям.
3. «Настройки → Cron log» — видно, какие фоновые задачи падают.
4. Код в git: `git log` в `tracker/slimtds-main` — можно откатиться на любую версию.
