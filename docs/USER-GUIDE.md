# AffMoment TDS — инструкция оператора (для новичка)

> Актуально на 2026-08-18. Этот файл — источник; docx-версия генерируется из него
> скриптом `docs/md2docx.py`. Меняется механика трекера — обновляем оба.

Эта инструкция написана так, чтобы понял человек, который открывает трекер впервые.
Термины объясняются по ходу. Если что-то кажется очевидным — просто читайте дальше.

---

## Часть 1. Что вообще делает этот трекер

Представьте цепочку, по которой идёт человек:

```
Ваш SEO-сайт  →  ТРЕКЕР  →  сайт партнёрки (казино/оффер)  →  партнёрка платит вам
   (реклама)    (эта тулза)     (куда уходит человек)         (и сообщает об этом трекеру)
```

Трекер — это «диспетчер трафика» посередине. Он делает четыре вещи:

1. **Ловит клик** — когда человек нажал на вашу ссылку, трекер записывает: из какой он страны,
   с телефона или компьютера, бот это или живой человек, откуда пришёл.
2. **Решает, куда его отправить** — по вашим правилам (например: «из Германии → на казино А,
   из Польши → на казино Б, ботов → на пустую страницу»).
3. **Перенаправляет** человека на сайт партнёрки (мгновенный редирект).
4. **Считает деньги** — когда человек зарегистрировался или внёс депозит, партнёрка «стучится»
   обратно в трекер (это называется *постбек*), и трекер записывает: вот регистрация, вот депозит,
   вот сумма выплаты.

Плюс трекер умеет **сверять свои цифры с отчётами партнёрки** — чтобы поймать, если партнёрка
«недоплатила» или потеряла ваши конверсии.

**Ключевые слова, которые дальше встречаются постоянно:**

- **Клик** — один переход человека через трекер.
- **Кампания** — «точка входа». У неё есть короткий адрес (slug), по которому идёт трафик.
- **Оффер** — конкретная ссылка партнёрки, куда в итоге уходит человек.
- **Поток (flow)** — правило внутри кампании: «кого куда отправлять».
- **Постбек** — сигнал от партнёрки трекеру: «на этом клике произошла регистрация/депозит».
- **Конверсия** — записанное трекером целевое действие (регистрация, депозит и т.д.).
- **Партнёрская сеть (ПП)** — партнёрка, чьи офферы вы льёте. В трекере это отдельная сущность
  с настройками (не обязательна, но полезна).

## Часть 2. Вход в трекер

- Адрес (локально): `http://localhost:8080/admin/login`. На сервере — ваш домен + `/admin/login`.
- Логин и пароль лежат в файле `.env` (`ADMIN_LOGIN` и `ADMIN_PASSWORD`).
- **Да, вход защищён паролем** — без него в админку не попасть, страница сразу перекидывает на форму входа.
  Есть защита от подбора: после нескольких неудачных попыток вход блокируется на время.
- **Трекер закрыт от поисковиков.** Google и другие краулеры не проиндексируют ни админку,
  ни адреса кампаний (настроено на уровне сервера — `robots.txt` + заголовок `noindex`).
  Отдельно настраивать ничего не нужно.

Если сайт не открывается вообще — значит не запущен Docker. Запустите Docker Desktop и подождите
~30 секунд, контейнеры поднимутся сами.

## Часть 3. Порядок настройки — почему именно такой

Сущности «цепляются» друг за друга, поэтому создавать их надо в правильном порядке. Если сделать
наоборот — не из чего будет выбирать. Правильный порядок:

```
(1) Партнёрская сеть  →  (2) Оффер  →  (3) Кампания  →  (4) Поток  →  (5) отдать URL постбека партнёрке
   [можно пропустить]      обязательно    обязательно     обязательно        обязательно для учёта денег
```

Разберём каждый шаг подробно, с примером. Пусть мы льём немецкое казино «BrandX».

---

### Шаг 1 (необязательный). Партнёрская сеть

**Зачем нужна.** Это «карточка партнёрки» с её особенностями. Нужна в двух случаях:
(а) партнёрка присылает постбек со своими названиями полей (не такими, как у нас по умолчанию),
(б) вы хотите защиту постбека по IP или удобную сверку отчётов.

**Если вы только начинаете — этот шаг можно пропустить** и вернуться к нему позже. Тогда трекер
будет ждать постбек в стандартном формате (об этом в шаге 5).

Меню **«Партнёрские сети» → «Добавить сеть»**. Поля:

- **Название** — как хотите, для себя. Например `BrandX Affiliates`.
- **Имена параметров постбэка** — заполнять, ТОЛЬКО если партнёрка жёстко диктует свои названия.
  Пример: партнёрка шлёт номер клика в поле `clickid`, а не `subid`; сумму — в `amount`, а не `payout`.
  Тогда вписываете их названия, и трекер поймёт. Если постбек-ссылку вы составляете сами (обычный
  случай) — оставьте значения по умолчанию, ничего не трогайте.
- **Перевод значений статуса** — если партнёрка присылает статус числом. Например у них `1` = одобрено,
  `0` = отклонено. Пишете по строке: `1=approved`, `0=rejected`. Наши статусы всегда:
  `approved` (одобрено), `pending` (в ожидании), `hold` (на удержании), `rejected` (отклонено).
- **Перевод значений событий** — партнёрки по-разному называют одно и то же. У одной депозит —
  `firstDeposit`, у другой — `FTD`, у третьей — `2`. Приводим к своему единому словарю, по строке:
  `firstDeposit=ftd`, `registration=reg`. Если значение не описано — оно просто пройдёт как есть,
  постбек с деньгами НИКОГДА не потеряется из-за этой таблицы.
- **IP-адреса источника постбеков** — защита денег. Партнёрки обычно публикуют, с каких IP они шлют
  постбеки. Вписываете их сюда (по одному в строке, можно диапазоны). Тогда постбек с чужого IP
  будет отклонён — чтобы никто не накрутил вам фейковых депозитов, зная адрес постбека. Оставите
  пусто — принимаются с любого IP (как раньше).

Нажимаете **«Сохранить»**.

### Шаг 2 (обязательный). Оффер

**Что это.** Конечная ссылка партнёрки — куда физически уходит человек.

Меню **«Оферы» → создать**. Поля:

- **Название** — для себя, например `BrandX DE`.
- **URL** — ссылка от партнёрки. **Самое важное:** внутри неё нужно вставить макрос `{click_id}`
  в то место, куда партнёрка ждёт номер клика (обычно параметр `subid` / `sub_id`). Пример:
  ```
  https://brandx-partners.com/redirect?offer=55&sub_id={click_id}
  ```
  `{click_id}` — это «плейсхолдер»: трекер подставит туда реальный номер клика в момент перехода.
  Именно по нему потом партнёрка и вернёт постбек, а трекер поймёт, к какому клику он относится.
  Доступны и другие макросы: `{country}` (страна), `{device_type}` (тип устройства),
  `{payout}` (сумма) и т.д.
- **Партнёрская сеть** — выбрать из списка, если создавали её в шаге 1. Не создавали — оставьте
  «по умолчанию».
- После сохранения у оффера появляется **postback token** — длинная строка. Запомните, где она:
  она понадобится в шаге 5, чтобы отдать партнёрке правильную ссылку постбека.

Один оффер можно использовать в нескольких кампаниях — офферы «глобальные».

---

### Шаг 3 (обязательный). Кампания

**Что это.** Точка входа трафика. Именно её адрес вы (или ваш SEO-сайт) даёте людям.

Меню **«Кампании» → создать**. Поля:

- **Название** — для себя, например `BrandX Germany`.
- **Slug** — короткий кусок адреса. Если slug `brandxde`, то ссылка клика будет
  `https://ваш-трекер/brandxde`. Именно по этому адресу пойдёт трафик.
- **Trash mode** («что делать с мусором») — что увидит человек, если НИ ОДИН поток ему не подошёл.
  Варианты: показать 404, 403, увести редиректом на запасной адрес, или отдать пустую страницу.
  Это «запасной выход», когда правила не сработали.

Сохраняете. Кампания создана, но пока «пустая» — трафик придёт и упрётся в trash mode, потому что
правил (потоков) ещё нет. Их добавляем в шаге 4.

---

### Шаг 4 (обязательный). Поток (flow) внутри кампании

**Что это.** Правило «кому какой оффер показать». У кампании может быть несколько потоков, они
проверяются сверху вниз, срабатывает первый подходящий.

Заходите в кампанию → раздел потоков → создать поток. Настраиваете:

- **Фильтры** — условия, кому этот поток. Гео (страна), устройство (моб/десктоп), ОС, бот/не бот,
  реферер и т.д. Внутри одной группы условия соединяются логикой И (должны выполниться все),
  между группами — ИЛИ. Пустой фильтр = «подходит всем».
  Пример для нашего кейса: фильтр `страна = DE` (Германия).
- **Target (куда отправлять)** — список офферов с весами. Вес — это доля трафика. Если поставить
  два оффера 50 и 50 — трафик поделится поровну (это и есть **сплит-тест**: проверить, какой оффер
  конвертит лучше). Один оффер весом 100 — весь трафик на него.
  Для примера: выбираем оффер `BrandX DE`, вес 100.

Сохраняете. Теперь немецкий трафик на `/brandxde` будет уходить на BrandX.

**Про клоакинг (если нужен).** Можно сделать отдельный поток с фильтром `бот = да` → увести ботов
на «белую» страницу, а живых людей другим потоком — на реальный оффер. Подробности —
в `docs/CLOAKING.md`.

### Шаг 5 (обязательный для учёта денег). Отдать партнёрке ссылку постбека

**Что происходит.** Когда у партнёрки случается регистрация или депозит, её система должна «постучать»
по специальному адресу трекера и передать: какой клик, что за событие, сколько денег. Этот адрес
вы даёте партнёрке (в её кабинете есть поле «postback URL» / «S2S postback»).

Шаблон ссылки, которую отдаёте партнёрке:

```
https://ваш-трекер/postback?token=<POSTBACK_TOKEN_ОФФЕРА>&subid={их_макрос_клика}&status={их_статус}&payout={их_сумма}&event_type={их_событие}&external_id={их_id_транзакции}
```

Разберём по частям:

- `token=...` — вставьте **postback token оффера** из шага 2. По нему трекер понимает, о каком
  оффере речь. (Можно использовать токен кампании — тогда оффер определится по самому клику.)
- `subid={их_макрос}` — сюда партнёрка подставит номер клика. У неё это свой макрос — например
  `{subid}`, `{sub_id1}`, `{s1}`. Смотрите в доке партнёрки, каким макросом она отдаёт то, что
  вы ей передали в `{click_id}`.
- `status={их_статус}` — одобрено/отклонено. Необязательно; если не прислать — считается `approved`.
- `payout={их_сумма}` — сумма выплаты.
- `event_type={их_событие}` — тип события (регистрация/депозит). Необязательно: без него событие
  запишется как «conversion». С ним регистрация, первый депозит и повторные депозиты на одном клике
  будут отдельными записями — это удобнее для аналитики.
- `external_id={их_id}` — id транзакции или игрока у партнёрки. Защищает от задвоения одной и той же
  выплаты.

**Проверка, что всё работает.** Меню **«Лог постбеков»** — там есть тестер (реально дёргает адрес
постбека, как это сделала бы партнёрка) и журнал каждого «стука» с результатом:

- `OK_NEW` — новая конверсия записана, всё хорошо.
- `OK_DUPLICATE` — повтор того же события, трекер не задвоил.
- `CLICK_NOT_FOUND` — трекер не нашёл клик по этому subid (партнёрка прислала не тот номер, или
  клик слишком старый).
- `FORBIDDEN_IP` — постбек пришёл с IP, которого нет в вашем белом списке (шаг 1).
- `INVALID_...` — что-то не так в данных постбека.

## Часть 4. Ежедневная работа

Разделы меню, которыми пользуетесь постоянно:

- **Клики** — каждый переход: страна, устройство, бот/не бот, на какой оффер ушёл.
- **Конверсии** — все зафиксированные события. Наверху — карточки-счётчики: сколько одобрено
  (approved), в ожидании (pending), на удержании (hold), отклонено (rejected), и суммы выплат.
  Ниже — таблица с фильтрами по статусу и типу события.
- **Статистика** — сводки: по кампаниям, офферам, странам и по вашим сайтам (какой SEO-сайт реально
  приносит деньги).
- **Сверка** (Партнёрские сети → у сети кнопка «Сверка») — самое важное для честного учёта. См. ниже.

### Как пользоваться Сверкой

Смысл: сравнить «сколько насчитал трекер» с «сколько показывает партнёрка в своём отчёте».

1. Скачайте у партнёрки её отчёт в формате CSV (по дням).
2. Партнёрские сети → у нужной сети откройте **«Отчёты ПП»** → загрузите файл → сопоставьте колонки
   (какая колонка — дата, какая — количество, какая — выплата). Это запоминается на будущее.
3. Откройте **«Сверка»**: таблица по дням и событиям — «наши / ПП» и дельта (расхождение в %).
   Строки, где расхождение больше порога (по умолчанию 10%), подсвечены. Настройте диапазон дат
   и порог вверху.

Замечание: строки могут «съезжать» на ±1 день вокруг полуночи — это нормально, потому что вы и
партнёрка считаете в разных часовых поясах. Смотрите на тренды и суммы за несколько дней, а не на
отдельную «полуночную» строку.

## Часть 5. Что важно понимать (частые вопросы)

- **«CLICK_NOT_FOUND» в логе постбеков** — партнёрка потеряла/обрезала номер клика, либо клик старше
  срока хранения (по умолчанию 365 дней). Если таких много — стоит проверить, правильный ли макрос
  клика настроен у партнёрки.
- **Отрицательная выплата — это нормально** при модели RevShare (игрок выиграл больше, чем проиграл).
  Трекер такое принимает и учитывает, не считает ошибкой.
- **Задвоение депозитов** — один и тот же `external_id` (транзакция) по одному типу события
  учитывается один раз, даже если партнёрка по ошибке прислала его на два разных клика.
- **Telegram-уведомления** — необязательны. Не настроены — просто ничего не приходит, на работу
  трекера это не влияет никак. Настроены — приходят уведомления о конверсиях и алерты. Отправка
  идёт через очередь, поэтому уведомления не тормозят ни редиректы, ни постбеки.
- **Бэкапы базы** — делаются автоматически каждую ночь, лежат в `var/backups/`. Восстановление
  проверено и работает.
- **Правки офферов и потоков** применяются за несколько секунд.

## Часть 6. Если что-то сломалось

1. Открывается ли админка? Нет → запустите Docker Desktop, подождите полминуты.
2. **«Лог постбеков»** — первое место, куда смотреть по деньгам/конверсиям: там видно каждый стук
   партнёрки и почему он прошёл или нет.
3. **Настройки → Cron log** — видно, какие фоновые задачи (бэкапы, обновление гео и т.п.) падают.
4. Ничего не помогло — код лежит в git, можно откатиться на любую рабочую версию (это уже забота
   того, кто разворачивал трекер).
