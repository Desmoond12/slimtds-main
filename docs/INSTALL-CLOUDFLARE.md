# AffMoment TDS — простая установка через Cloudflare (шаг за шагом)

> Актуально на 2026-08-18. Самый простой способ поднять трекер: за Cloudflare, режим `cf_flex`.
> HTTPS и защиту делает Cloudflare, сервер остаётся простым. Источник для docx (`docs/md2docx.py`).

Это инструкция «делай ровно так». Каждый шаг: что нажать / куда вписать / что должно получиться.
Если пункт кажется мелочью — всё равно не пропускайте, порядок важен.

Понадобится: сервер (VPS) с Ubuntu, домен, аккаунт Cloudflare (бесплатный). Всё.

---

## Общая картина (чтобы не потеряться)

```
Посетитель ──HTTPS──> Cloudflare ──HTTP──> ваш сервер (трекер)
             замок      прячет IP,          Caddy+приложение
           делает CF    фильтрует ботов
```

Cloudflare берёт на себя HTTPS (замок в браузере), прячет реальный IP сервера и отбивает атаки.
Сервер держит только сам трекер. Никакого Let's Encrypt и nginx настраивать не нужно.

---

## ШАГ 1. Завести сервер (VPS)

1. Купите у любого хостера VPS: Ubuntu 22.04 или 24.04, минимум 2 ГБ RAM, ~10 ГБ диска.
2. Хостер пришлёт: **IP-адрес сервера** и **пароль root** (или SSH-ключ). Запишите IP — он нужен дальше.

**Что должно получиться:** есть IP сервера и способ на него зайти.

---

## ШАГ 2. Подключить домен к Cloudflare

1. Зарегистрируйтесь на **cloudflare.com** (бесплатный план).
2. Нажмите **«Add a site»**, введите свой домен (например `mysite.com`), выберите **Free**.
3. Cloudflare покажет **два адреса своих nameservers** (вида `xxx.ns.cloudflare.com`). Скопируйте их.
4. Зайдите в панель, где вы покупали домен (регистратор), найдите настройку **Nameservers / DNS-серверы**
   и **замените** тамошние серверы на два от Cloudflare. Сохраните.
5. Вернитесь в Cloudflare и дождитесь письма/статуса **«Active»** (обычно от нескольких минут до пары часов —
   пока обновятся DNS).

**Что должно получиться:** домен в Cloudflare помечен как **Active**.

---

## ШАГ 3. Направить домен на сервер (DNS-запись в Cloudflare)

1. В Cloudflare слева выберите **DNS → Records → Add record**.
2. Заполните:
   - **Type:** `A`
   - **Name:** если трекер будет на поддомене `track.mysite.com` — впишите `track`.
     Если на самом домене `mysite.com` — впишите `@`.
   - **IPv4 address:** IP вашего сервера из шага 1.
   - **Proxy status:** ОБЯЗАТЕЛЬНО **оранжевое облачко (Proxied)** — включено. Это и есть защита и HTTPS.
3. Save.

**Что должно получиться:** в списке DNS есть запись `A` с оранжевым облачком на ваш IP.

---

## ШАГ 4. Включить HTTPS в Cloudflare (режим Flexible)

1. В Cloudflare слева: **SSL/TLS → Overview**.
2. Режим шифрования поставьте **Flexible**.
   (Означает: посетитель ↔ Cloudflare — по HTTPS с замком; Cloudflare ↔ ваш сервер — по простому HTTP.
   Сервер при этом мы закроем файрволом только для Cloudflare — шаг 7.)
3. Зайдите в **SSL/TLS → Edge Certificates** и включите **«Always Use HTTPS»** (On).

**Что должно получиться:** SSL-режим = Flexible, Always Use HTTPS = On.

---

## ШАГ 5. Зайти на сервер и установить Docker

Подключитесь к серверу (в терминале Windows — `ssh root@ВАШ_IP`, введите пароль).

Скопируйте команды по очереди (для Ubuntu):

```
apt-get update
apt-get install -y ca-certificates curl gnupg
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" > /etc/apt/sources.list.d/docker.list
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

Ещё поставьте две маленькие программы — `make` (запускает готовые команды трекера) и `git`
(на случай, если будете забирать код через git). Одной строкой:

```
apt-get install -y make git
```

**Что должно получиться:** команды `docker --version`, `docker compose version` и `make --version`
печатают версии (не «command not found»).

## ШАГ 6. Перенести программу трекера на сервер

Сама программа сейчас лежит папкой у вас на компьютере (Windows). Её надо скопировать на сервер.
Самый понятный способ — программой **WinSCP** (это как проводник, но одна половина окна — ваш
компьютер, вторая — сервер, файлы перетаскиваются мышкой). Ниже — по шагам.

> **ВНИМАНИЕ, это важно.** Внутри папки трекера есть две ОЧЕНЬ большие папки — **`docker-app`** и
> **`docker-data`** (десятки гигабайт, это сам Docker, а не трекер). **Их копировать НЕ нужно** —
> иначе перенос будет идти часами и забьёт весь сервер. Ниже показано, как их пропустить.

### 6.1. Установить WinSCP (на вашем компьютере)

1. Откройте сайт **winscp.net**, скачайте и установите WinSCP (обычная установка «Далее-Далее»).
2. Запустите его.

### 6.2. Подключиться к серверу

В открывшемся окне входа заполните:

- **File protocol (протокол):** `SFTP`
- **Host name (адрес):** IP вашего сервера (из шага 1)
- **Port number (порт):** `22`
- **User name (пользователь):** `root`
- **Password (пароль):** пароль сервера (из шага 1)

Нажмите **Login**. Если спросит про ключ сервера — нажмите **Yes / Accept**.

**Что должно получиться:** открылось окно из двух половин. Слева — ваш компьютер, справа — сервер
(вы в папке `/root`).

### 6.3. Создать папку на сервере

Справа (на сервере) щёлкните правой кнопкой по пустому месту → **New → Directory** → введите имя
`slimtds` → OK. Двойным щелчком зайдите внутрь этой папки `slimtds`.

### 6.4. Скопировать файлы (без двух больших папок)

1. Слева (ваш компьютер) зайдите в папку трекера:
   `D:\SOFT\SiteCombo1\tracker\slimtds-main`.
2. Выделите **все файлы и папки, КРОМЕ `docker-app` и `docker-data`**. Проще всего так: нажмите
   `Ctrl+A` (выделить всё), затем зажмите `Ctrl` и щёлкните по `docker-app` и по `docker-data`,
   чтобы снять с них выделение.
3. Перетащите выделенное мышкой в правую половину (в папку `slimtds` на сервере). Начнётся
   копирование — подождите несколько минут.

**Что должно получиться:** справа, в папке `slimtds`, появились файлы трекера (`Makefile`, `config`,
`src`, `docs` и т.д.), но НЕТ папок `docker-app` и `docker-data`.

> **Второй способ, если вы дружите с git** (пропустите, если делаете через WinSCP): загрузите папку
> трекера в приватный репозиторий на GitHub, а на сервере выполните `git clone <адрес> slimtds`.
> Плюс способа — git сам не копирует большие папки (они и так исключены). Минус — надо разобраться
> с доступом к приватному репозиторию.

### 6.5. Создать файл настроек

Вернитесь в окно, где вы подключены к серверу по SSH (не WinSCP, а терминал из шага 5), и выполните:

```
cd slimtds
make env
```

`make env` создаёт файл настроек **`.env`** и сам придумывает секретный ключ и пароль администратора.

**Что должно получиться:** внизу вывода видно строку `ADMIN_PASSWORD=...` — **скопируйте этот пароль
себе, он понадобится для входа.** (Если вместо этого написано `.env already exists` — значит файл
настроек уже скопировался с вашего компьютера, это тоже нормально: пароль посмотрите командой
`grep ADMIN_PASSWORD .env`, а если он пустой — впишете свой в следующих шагах.)

---

## ШАГ 7. Закрыть сервер файрволом (только для Cloudflare)

Так как в режиме Flexible сервер общается с Cloudflare по обычному HTTP, закроем его от всех, кроме
Cloudflare. Скопируйте блок целиком:

```
ufw allow 22/tcp                      # SSH — ПЕРВЫМ, иначе отрежете себе доступ
for ip in $(curl -s https://www.cloudflare.com/ips-v4) $(curl -s https://www.cloudflare.com/ips-v6); do
  ufw allow from "$ip" to any port 80 proto tcp
  ufw allow from "$ip" to any port 443 proto tcp
done
ufw --force enable
```

**Что должно получиться:** `ufw status` показывает правило на 22 и правила на 80/443 с адресов Cloudflare.
Теперь напрямую по IP к трекеру никто не достучится — только через Cloudflare.

## ШАГ 8. Настроить файл `.env`

Откройте: `nano .env`. Найдите и выставьте эти строки (Ctrl+O сохранить, Ctrl+X выйти):

| Строка в `.env` | Впишите | Что это |
|---|---|---|
| `APP_ENV=` | `prod` | боевой режим |
| `APP_DEBUG=` | `false` | не показывать детали ошибок |
| `DEPLOY_MODE=` | `cf_flex` | режим «за Cloudflare» |
| `DOMAIN=` | `track.mysite.com` | ваш домен (как в DNS-записи) |
| `APP_URL=` | `https://track.mysite.com` | полный адрес админки |
| `DB_PASSWORD=` | придумайте свой пароль | пароль базы — вписать СЕЙЧАС, до первого запуска |

`APP_SECRET` и `ADMIN_PASSWORD` уже заполнены автоматически — не трогайте.

> **Важно про `DB_PASSWORD`:** база запоминает его при самом первом старте. Поменяете позже — база
> останется со старым, а приложение будет слать новый, и будет ошибка. Поэтому впишите сразу.

Остальное можно не трогать. `TELEGRAM_*` и `MAXMIND_*` — по желанию, позже (см. большую инструкцию
`AffMoment-TDS-установка-VPS`).

## ШАГ 9. Запустить трекер

```
make prod-up-cf
```

Первый запуск собирает всё нужное — несколько минут, это нормально.

**Что должно получиться:** `docker compose ps` показывает контейнеры `app`, `db`, `cron` в состоянии
`Up`, у `app` — `healthy`.

---

## ШАГ 10. Создать базу и администратора

Выполните эти три команды **по очереди, в том же окне SSH** (каждую — целиком одной строкой,
нажимая Enter). Все три начинаются одинаково — это не опечатка, так и надо:

```
# 1. Создать таблицы в базе
docker compose -f docker-compose.yml -f docker-compose.prod.cf.yml run --rm --entrypoint="" app vendor/bin/phinx migrate -c phinx.php

# 2. Подготовить «партиции» (без этого первый же клик выдаст ошибку)
docker compose -f docker-compose.yml -f docker-compose.prod.cf.yml exec app php bin/console partitions:rotate

# 3. Создать администратора (логин и пароль берёт из .env, только один раз)
docker compose -f docker-compose.yml -f docker-compose.prod.cf.yml exec app php bin/console admin:init
```

**Что должно получиться:** все три команды отработали без красных строк с ошибками.

## ШАГ 11. Проверить, что всё работает

В браузере откройте: **`https://track.mysite.com/admin/login`** — должна открыться страница входа
с замком HTTPS. Войдите логином `admin` и паролем из `.env` (шаг 6).

Проверка из терминала сервера (подставьте домен):

```
DOMAIN=track.mysite.com
curl -sf "https://$DOMAIN/__health" -o /dev/null -w '%{http_code}\n'   # 200
curl -s  "https://$DOMAIN/robots.txt"                                  # Disallow: /
```

**Что должно получиться:** `/__health` = `200`, `robots.txt` показывает `Disallow: /` (значит трекер
закрыт от поисковиков — это уже настроено, ничего делать не нужно).

Готово. Трекер работает за Cloudflare, с HTTPS, скрытым IP и закрытый от индексации.

## Важные заметки для трекера за Cloudflare

- **Реальный IP посетителя** трекер уже правильно берёт из заголовка Cloudflare — гео и антибот
  работают корректно, ничего настраивать не надо.
- **Cloudflare может мешать рекламному трафику.** Если у вас включён агрессивный «Bot Fight Mode»
  или высокий Security Level — Cloudflare может показывать проверку/капчу вашим посетителям на адресах
  кампаний. Для трекера обычно ставят щадящий уровень безопасности или правило (Configuration Rule)
  на путь редиректов. Это ваша зона — просто держите в голове, если увидите падение трафика.
- **Хотите шифрование ещё и между Cloudflare и сервером** (режим `cf_full`, сертификат от Cloudflare)?
  Это следующий уровень надёжности для постбеков с деньгами — скажите, распишу отдельно.

## Если что-то не так

| Что видите | Причина | Что делать |
|---|---|---|
| Сайт не открывается по домену | DNS ещё не обновился, или облачко в Cloudflare серое (не Proxied) | Подождите; проверьте, что в DNS-записи оранжевое облачко включено |
| Ошибка «слишком много редиректов» в браузере | Режим SSL в Cloudflare не Flexible | SSL/TLS → Overview → поставьте **Flexible** |
| Админка без оформления | Запустили голый `docker compose up` вместо `make prod-up-cf` | `make prod-down`, затем `make prod-up-cf` |
| Контейнер `app` перезапускается | Ошибка в `.env` или не сделали шаг 10 | `make logs` — покажет текст ошибки |
| Ошибка входа в базу | Поменяли `DB_PASSWORD` после первого запуска | Верните старый пароль; либо (это **удалит все данные**) выполните `docker compose -f docker-compose.yml -f docker-compose.prod.cf.yml down -v` и начните с шага 9 |
