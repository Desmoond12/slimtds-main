# AffMoment TDS — установка на сервер (VPS), для новичка

> Актуально на 2026-08-18. Источник для docx (`docs/md2docx.py`). Меняется деплой — обновляем оба.
> Всё основано на реальном устройстве проекта (`docs/DEPLOYMENT.md`, `docs/AI-INSTALL.md`, `.env.example`),
> не выдумано.

Эта инструкция для человека, который впервые ставит трекер на сервер. Команды можно копировать
как есть. После важных шагов написано, **что вы должны увидеть**, если всё хорошо.

---

## Часть 0. Сначала — короткий словарь

- **VPS** — арендованный сервер в интернете (у хостера). У него есть публичный IP-адрес.
- **SSH** — способ подключиться к серверу из терминала и вводить команды. Обычно
  `ssh root@ВАШ_IP`.
- **Docker** — программа, которая запускает приложение в «коробке» (контейнере) со всем нужным
  внутри. Благодаря ему на сервер НЕ надо ставить PHP, базу, веб-сервер по отдельности — всё уже
  внутри образа. Docker поставим на шаге 2.
- **Домен** — например `track.mysite.com`. Нужен, чтобы к трекеру обращаться по имени, а не по IP,
  и чтобы работал HTTPS (замок в браузере).
- **Веб-сервер** — программа, которая принимает запросы из интернета. **Важно: в этом трекере это
  НЕ nginx, а Caddy** (он встроен внутрь приложения, отдельно ставить не нужно). Caddy сам получает
  и продлевает SSL-сертификат. Если вы привыкли к nginx — здесь его нет и не требуется.
- **`.env`** — текстовый файл с настройками (пароли, домен, режим). Главный файл, который вы правите.

## Часть 1. Что понадобится (проверьте заранее)

- **VPS на Linux** (проще всего Ubuntu или Debian), доступ root или sudo.
  Минимум ~2 ГБ оперативной памяти, ~10 ГБ свободного диска.
- **Домен**, направленный на IP вашего сервера (как это сделать — шаг 3).
- Опционально: аккаунт **MaxMind** (бесплатный, для определения страны/города по IP) и
  **Telegram-бот** (для уведомлений). Без них трекер работает, просто без гео и без уведомлений.

Ставить PHP, Composer, Node вручную **не нужно** — всё собирается внутри Docker.

## Часть 2. Выбор режима работы (один параметр — DEPLOY_MODE)

У трекера три способа «смотреть в интернет». Выберите свой — от этого зависят пара настроек.

| Режим | Когда выбирать | Кто делает HTTPS |
|---|---|---|
| **direct** | Обычный сервер, домен смотрит прямо на него. **Это выбор по умолчанию для новичка.** | Caddy сам, бесплатно (Let's Encrypt) |
| **cf_flex** | Домен спрятан за Cloudflare, между Cloudflare и сервером — обычный HTTP | Cloudflare |
| **cf_full** | Домен за Cloudflare И на сервере тоже HTTPS (сертификат от Cloudflare) | Cloudflare + сертификат на сервере |

Дальше вся инструкция идёт по режиму **direct** (самый простой). Где для Cloudflare что-то иначе —
отдельно помечено.

## Часть 3. Домен и проверка портов

**Направьте домен на сервер.** В панели, где куплен домен (или в DNS-хостинге), создайте запись
типа **A**: имя вашего домена → публичный IP сервера. Если используете Cloudflare — включите
оранжевое облачко (проксирование).

Проверка (может занять от минут до пары часов, пока DNS обновится): выполните на своём компьютере
`ping track.mysite.com` — должен отвечать IP вашего сервера.

**Проверьте, что порты 80 и 443 свободны на сервере** (их занимает веб-сервер; если там уже что-то
висит — будет конфликт). На сервере:

```
ss -lntp | grep -E ':(80|443)\s' || echo "ПОРТЫ СВОБОДНЫ"
```

Должно напечатать **`ПОРТЫ СВОБОДНЫ`**. Если вместо этого показало какие-то строки — значит порт
занят (например уже стоит nginx/apache). Разберитесь с этим до продолжения — это самая частая
причина «наполовину рабочей» установки.

## Часть 4. Установить Docker

Скопируйте команды по одной (для Ubuntu):

```
apt-get update
apt-get install -y ca-certificates curl gnupg
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" > /etc/apt/sources.list.d/docker.list
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

(Если у вас Debian, а не Ubuntu — замените слово `ubuntu` на `debian` в двух местах выше.)

**Проверка — что должно получиться:**

```
docker --version           # покажет версию, например Docker version 27.x
docker compose version     # покажет версию Compose, например v2.x
```

Если обе команды печатают версии — Docker готов.

## Часть 5. Файрвол — не заблокируйте себе доступ

Файрвол закрывает лишние двери сервера. **Критично: сначала разрешите SSH (порт 22), потом
включайте файрвол** — иначе отрежете себе вход на сервер.

```
ufw allow 22/tcp        # СНАЧАЛА SSH — иначе потеряете доступ к серверу
ufw allow 80/tcp
ufw allow 443/tcp
ufw --force enable
```

Для режимов Cloudflare есть смысл открыть 80/443 не всему миру, а только адресам Cloudflare
(чтобы никто не обошёл защиту, зайдя напрямую по IP). Пример такой настройки — в `docs/DEPLOYMENT.md`.
Для новичка на `direct` — достаточно команд выше.

## Часть 6. Загрузить трекер на сервер

Код трекера хранится в git. Способа два:

- Если у вас есть приватный git-репозиторий с трекером:
  ```
  git clone <адрес-вашего-репозитория> slimtds
  ```
- Или перенесите папку трекера с рабочего компьютера через `scp`/`rsync` (без тяжёлых папок
  `docker-app/`, `docker-data/`, `node_modules/`, `vendor/` — они не нужны на сервере).

Зайдите в папку и создайте файл настроек:

```
cd slimtds        # (или как называется папка)
make env
```

`make env` создаёт файл `.env` из шаблона и сам придумывает случайные `APP_SECRET` (ключ для
безопасности) и `ADMIN_PASSWORD` (пароль администратора). **Он не перезапишет уже существующий
`.env`** — если файл есть, команда остановится, и это правильно.

## Часть 7. Настроить файл `.env` (главные параметры)

Откройте `.env` любым редактором (`nano .env`). Ниже — что менять. **Обязательно поправьте:**

| Параметр | Простыми словами | Что поставить (direct) |
|---|---|---|
| `APP_ENV` | Режим: разработка или боевой | `prod` |
| `APP_DEBUG` | Показывать ли подробности ошибок (в бою — выключить) | `false` |
| `DEPLOY_MODE` | Способ работы из части 2 | `direct` |
| `DOMAIN` | Ваш домен | `track.mysite.com` |
| `APP_URL` | Полный адрес админки | `https://track.mysite.com` |
| `APP_SECRET` | Секретный ключ (подпись входа) | уже сгенерирован `make env`, не трогайте |
| `ADMIN_LOGIN` | Логин администратора | `admin` |
| `ADMIN_PASSWORD` | Пароль администратора | сгенерирован `make env` — **запишите его себе!** |
| `DB_PASSWORD` | Пароль базы данных | **придумайте свой и впишите СЕЙЧАС** (см. предупреждение) |
| `APP_TZ` | Часовой пояс для отчётов | например `Europe/Moscow` |

> **Важное предупреждение про `DB_PASSWORD`.** База запоминает пароль в момент самого первого запуска.
> Если поменять его ПОСЛЕ первого старта — база останется со старым паролем, а приложение будет
> слать новый, и получится ошибка входа в базу. Поэтому впишите пароль базы сразу, до первого запуска.

**Необязательные параметры** (можно оставить как есть):

| Параметр | Зачем | По умолчанию |
|---|---|---|
| `RATE_LIMIT_PUBLIC` | Ограничение частоты постбеков/пикселя с одного IP в минуту. Поднимите, если у вас очень много трафика и упираетесь. | `120` |
| `MAXMIND_ACCOUNT_ID` / `MAXMIND_LICENSE_KEY` | Ключи для определения гео по IP (часть 9) | пусто |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | Уведомления в Telegram (часть 10) | пусто |
| `TRUSTED_PROXIES` | Заполнять, только если перед трекером стоит ваш собственный доп. прокси. Обычно — пусто. | пусто |

Про определение реального IP посетителя: на `direct` без своего прокси — оставьте `TRUSTED_PROXIES`
пустым, всё определится само. На Cloudflare (`cf_*`) — тоже пусто, адреса Cloudflare трекер знает сам.

Файлы `Caddyfile.*` руками НЕ трогайте — нужный выбирается автоматически по `DEPLOY_MODE`.

## Часть 8. Запустить трекер

```
make prod-up-direct     # для режима direct
# для Cloudflare вместо этого: make prod-up-cf
```

Первый запуск **собирает образ** (скачивает и складывает всё нужное) — это несколько минут, так и
должно быть. Дождитесь окончания.

> **Никогда не запускайте просто `docker compose up` на боевом сервере.** Такая команда «подменит»
> собранные файлы стилей и скриптов, и получится админка без оформления и неработающий пиксель, хотя
> с виду всё «запущено». Используйте только `make prod-up-direct` / `make prod-up-cf`.

**Проверка — что должно получиться:**

```
docker compose ps
```

Должны быть контейнеры `app`, `db`, `cron` в состоянии `Up`, а у `app` — `healthy`.

## Часть 9. Первичная настройка базы и администратора

Сначала «объявим» пару команд, чтобы дальше было короче (для direct):

```
DC="docker compose -f docker-compose.yml -f docker-compose.prod.direct.yml"
# для Cloudflare: DC="docker compose -f docker-compose.yml -f docker-compose.prod.cf.yml"
```

Теперь строго по порядку:

```
# 1. Создать таблицы в базе
$DC run --rm --entrypoint="" app vendor/bin/phinx migrate -c phinx.php

# 2. Подготовить «партиции» — без этого шага первый же клик выдаст ошибку 500
$DC exec app php bin/console partitions:rotate

# 3. Создать администратора (возьмёт логин/пароль из .env, только один раз)
$DC exec app php bin/console admin:init
```

После этого можно зайти в админку: `https://ваш-домен/admin/login`.

## Часть 10 (необязательно). Определение страны по IP (MaxMind)

Чтобы трекер знал страну/город/оператора посетителя (для гео-правил), нужны бесплатные базы MaxMind.

1. Зарегистрируйтесь на maxmind.com, создайте «License Key», впишите `MAXMIND_ACCOUNT_ID` и
   `MAXMIND_LICENSE_KEY` в `.env`.
2. Скачайте базы (работает в любом режиме):

```
docker run --rm \
  -e GEOIPUPDATE_ACCOUNT_ID="ВАШ_ID" \
  -e GEOIPUPDATE_LICENSE_KEY="ВАШ_КЛЮЧ" \
  -e GEOIPUPDATE_EDITION_IDS="GeoLite2-Country GeoLite2-City GeoLite2-ASN" \
  -v "$PWD/geoip-data:/usr/share/GeoIP" \
  maxmindinc/geoipupdate:latest
ls geoip-data/        # должно появиться три файла .mmdb
$DC restart app       # чтобы трекер подхватил базы
```

Дальше базы обновляются сами раз в сутки. Без баз гео-фильтры просто не срабатывают — это не ошибка.

## Часть 11 (необязательно). Уведомления в Telegram

Если не нужно — пропустите, на работу трекера это не влияет.

1. Напишите боту **@BotFather** в Telegram, создайте бота, скопируйте его токен.
2. Узнайте свой chat_id: перешлите любое сообщение боту **@userinfobot**, он ответит числом.
3. Впишите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env`, затем `$DC up -d --force-recreate app cron`.
4. Проверка: `$DC exec app php bin/console telegram:alerts`.

## Часть 12. Финальная проверка (всё ли готово)

Подставьте свой домен и выполните:

```
DOMAIN=track.mysite.com

$DC ps                                                              # app/db/cron — Up, app healthy
curl -sf "https://$DOMAIN/__health" -o /dev/null -w '%{http_code}\n' # должно быть 200
curl -sI "https://$DOMAIN/admin/login" | head -1                    # должно быть HTTP/2 200
```

**Что должно получиться:** контейнеры живые, `/__health` отдаёт `200`, страница входа открывается.
Замок HTTPS в браузере — зелёный/без ошибок.

**Заодно проверьте, что трекер закрыт от поисковиков** (это уже настроено, просто убедитесь):

```
curl -s "https://$DOMAIN/robots.txt"                                # покажет "Disallow: /"
curl -sI "https://$DOMAIN/admin/login" | grep -i x-robots           # покажет "noindex, nofollow..."
```

Домен трекера закрыт от индексации Google и других краулеров: `robots.txt` запрещает обход всего
домена, а на админку дополнительно отдаётся заголовок `noindex`. Отдельно ничего настраивать не надо.

## Часть 13. Что делать после установки

- Смените пароль администратора в **`/admin/settings`** (первый пароль был сгенерирован автоматически).
- Начните настройку кампаний/офферов — по инструкции оператора (`AffMoment-TDS-инструкция.docx`),
  там всё по шагам.
- Направьте трафик на адрес кампании: движок отвечает по адресу `https://ваш-домен/<slug-кампании>`.
- Бэкапы делаются автоматически каждую ночь и лежат в `./var/backups/` на сервере. Восстановление
  из бэкапа: `$DC exec app php bin/console db:restore ИМЯ_ФАЙЛА.dump yes`.

## Часть 14. Если что-то пошло не так

| Что видите | В чём причина | Что делать |
|---|---|---|
| Админка без оформления, пиксель не грузится | Запустили голый `docker compose up` вместо `make prod-up-*` | `make prod-down`, затем `make prod-up-direct` |
| Контейнер `app` постоянно перезапускается | Ошибка в `.env` или не прошли миграции | `make logs` — увидите текст ошибки; частая причина — забыли шаг миграций (часть 9) |
| HTTPS-сертификат не выдаётся | Домен не смотрит на сервер, или занят порт 80 | Перепроверьте часть 3; для выпуска сертификата порт 80 должен быть доступен из интернета |
| Ошибка входа в базу данных | Поменяли `DB_PASSWORD` уже после первого запуска | Верните старый пароль, либо `$DC down -v` (**УДАЛИТ все данные**) и начните заново |
| Гео-фильтры не срабатывают | Не скачаны базы MaxMind | Выполните команду из части 10 и перезапустите `app` |
| Посетители все с одинаковым IP | Перед трекером стоит ваш прокси, не указанный в `TRUSTED_PROXIES` | Впишите IP прокси в `TRUSTED_PROXIES`, перезапустите; либо используйте режим Cloudflare |
